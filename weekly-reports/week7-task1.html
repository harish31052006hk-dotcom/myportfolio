On / Off Inbuilt LED on ESP32

Control the ESP32 onboard LED wirelessly through a local browser-based HTTP server.

1. Overview

In this experiment, the ESP32 functions as a standalone local HTTP web server connected to a Wi-Fi network. By hosting a lightweight web page directly on the microcontroller, the device listens for incoming HTTP requests initiated from any web browser on the same local subnet.


When a user visits the assigned local IP address and clicks the interactive on-screen controls, the browser issues specific HTTP request endpoints (/on and /off). The ESP32 parses these URIs, toggles digital output pin GPIO 2 connected to the onboard surface-mount device (SMD) LED, and immediately returns dynamically updated HTML content confirming the live operational state of the LED.

2. Objective

The primary objective of this assignment is to demonstrate the capability of the ESP32 microcontroller to serve as a self-hosted embedded HTTP web server, enabling wireless LED control directly from a standard web browser — without any cloud infrastructure or external server.


  • Configure the ESP32 as an HTTP web server operating on port 80 over a local Wi-Fi network.
  • Serve a dynamic HTML control interface that reflects the real-time state of the onboard LED (GPIO 2).
  • Respond to browser-initiated HTTP requests at endpoints /on and /off to toggle the LED state.
  • Print the assigned IP address to the Serial Monitor so the web interface can be accessed from any device on the same subnet.
  • Validate end-to-end wireless actuation — from browser click to observable physical LED response — within a local area network.

3. Problem Statement

Traditional embedded systems require physical access to a device or proprietary wired interfaces (UART, SPI, I²C) to control hardware outputs. This creates practical limitations in scenarios where remote, wireless, or hands-free control is necessary.


This experiment addresses the following problem: How can an ESP32-connected LED be controlled remotely through a local web interface without any cloud dependency, mobile application, or dedicated protocol such as MQTT?


The solution requires the ESP32 to independently host a responsive HTML control panel reachable via any browser on the same local network, bridge browser-level HTTP GET requests to GPIO output actions, and return immediate state feedback — all executing concurrently on the microcontroller's main loop with no dedicated operating system or additional hardware.

4. Introduction

The ESP32 (Espressif Systems ESP-WROOM-32) is a dual-core 32-bit microcontroller featuring integrated 802.11 b/g/n Wi-Fi and Bluetooth 4.2 / BLE radios. It operates at up to 240 MHz, with 520 KB SRAM and 4 MB flash, making it capable of running lightweight network stacks entirely in firmware — a foundational building block for the Internet of Things (IoT).


Wi-Fi Connectivity: The ESP32's integrated Wi-Fi radio operates in Station (STA) mode for this experiment, associating with an existing wireless access point using SSID and password credentials. After a successful DHCP lease, the device obtains a local IPv4 address, enabling it to communicate over TCP/IP within the subnet — without any external networking hardware.


Embedded Web Servers: An embedded HTTP web server is a lightweight TCP socket listener running directly on a microcontroller, implementing a minimal subset of the HTTP/1.1 protocol. The Arduino-compatible WebServer.h library (part of the ESP32 Arduino core) abstracts TCP connection management, HTTP header parsing, and response generation — exposing a simple URI-based routing API similar to Node.js Express.


HTML-Based Control: By returning valid HTML documents as HTTP responses, the ESP32 transforms any standard web browser into a zero-install control interface. Interactive anchor elements styled as buttons allow users to issue HTTP GET requests to specific URIs (/on, /off), which the ESP32 interprets as GPIO actuation commands. The returned page also displays the current LED state using a live digitalRead() call, providing immediate visual feedback.

5. Working Principle

The system operates on a request-response cycle where every browser interaction triggers a chain of events from the network stack through to physical GPIO actuation:

Step 1 — Browser Request

The user opens a browser and navigates to http://192.168.56.206 or clicks the TURN ON / TURN OFF button. The browser constructs an HTTP GET request (e.g., GET /on HTTP/1.1) and transmits it to the ESP32's IP address over TCP port 80.

Step 2 — TCP Socket Reception

The server.handleClient() call inside the loop() function continuously polls the TCP stack. When an incoming connection arrives on port 80, the library accepts the socket, reads the HTTP request headers, and extracts the requested URI path.

Step 3 — URI Routing

The extracted URI is matched against registered route handlers. / routes to handleRoot(), /on routes to handleLEDOn(), and /off routes to handleLEDOff(). The matching handler function is then invoked.

Step 4 — GPIO Actuation

Inside handleLEDOn(), digitalWrite(ledPin, HIGH) drives GPIO 2 to 3.3 V, illuminating the onboard SMD LED. Inside handleLEDOff(), digitalWrite(ledPin, LOW) pulls GPIO 2 to 0 V, extinguishing the LED.

Step 5 — Dynamic HTML Response

After GPIO actuation, each handler calls htmlPage(), which reads the live state of GPIO 2 via digitalRead(ledPin) and embeds it as "ON" or "OFF" in the HTML string. server.send(200, "text/html", htmlPage()) delivers this response to the browser.

Step 6 — Continuous Polling Loop

The loop() function contains only server.handleClient(), which runs indefinitely. This non-blocking call means the ESP32 remains fully responsive to new HTTP connections at any time, processing each request within a single loop iteration.

13. Code Breakdown

WiFi.h

Manages Wi-Fi station connectivity, handles radio association with the wireless router using the provided SSID/password credentials, and exposes connection state methods such as WiFi.status() and WiFi.localIP().

WebServer.h

Provides the lightweight HTTP server implementation for ESP32. It enables URI route registration, parsing of incoming HTTP request headers, and sending HTTP responses with appropriate status codes and MIME types.

GPIO 2

The physical digital pin hardwired to the ESP32 development board's blue surface-mount LED. Configured as an OUTPUT and actuated between HIGH (3.3V) and LOW (0V).

WebServer(80)

Instantiates the HTTP server object bound to port 80, the standard default port for HTTP traffic, allowing clients to access the page without specifying a port suffix.

/ (Root Endpoint)

Root URI handler mapped to handleRoot(). Returns HTTP status 200 with the rendered control interface displaying the current operational state of the onboard LED.

/on (Turn On)

Action endpoint mapped to handleLEDOn(). Invokes digitalWrite(ledPin, HIGH) to illuminate the onboard LED, then serves the updated HTML page with "ON" state.

/off (Turn Off)

Action endpoint mapped to handleLEDOff(). Invokes digitalWrite(ledPin, LOW) to turn off the onboard LED, then serves the updated HTML page with "OFF" state.

server.handleClient()

Non-blocking function called in every iteration of loop(). Listens for incoming TCP socket connections, parses client HTTP requests, and routes them to registered handlers.

dynamic HTML

Constructed using C++ raw string literals (R"rawliteral(...)rawliteral") to embed CSS styling and markup directly in program memory. Concatenates the live evaluation of digitalRead(ledPin) to dynamically reflect the real-time LED state on the page.

14. HTML Web Interface

The ESP32 serves a dynamically generated HTML page as the control interface. The page is constructed inside the htmlPage() function using C++ raw string literals and string concatenation, embedding live GPIO state into each response.

Page Title & Viewport

The HTML <head> sets <title>ESP32 LED Control</title> and includes a meta viewport tag for responsive rendering on mobile devices.

Inline CSS Styling

A <style> block embedded in the page sets a dark background (#111), white text, centred layout, and defines two button classes: .on (green #00c853) and .off (red #d50000).

TURN ON Button

An anchor element <a class="button on" href="/on">TURN ON</a> styled as a green button. Clicking it causes the browser to issue an HTTP GET to http://192.168.56.206/on, which invokes handleLEDOn() and drives GPIO 2 HIGH.

TURN OFF Button

An anchor element <a class="button off" href="/off">TURN OFF</a> styled as a red button. Clicking it issues an HTTP GET to http://192.168.56.206/off, invoking handleLEDOff() and driving GPIO 2 LOW.

Live LED State Indicator

A paragraph element <p>LED State: <strong>[STATE]</strong></p> displays the real-time LED state. The [STATE] placeholder is dynamically replaced by the result of digitalRead(ledPin) ? "ON" : "OFF" evaluated at the exact moment the response is generated, so every page load reflects the true current GPIO output.

15. Execution Procedure

Steps required to upload the firmware and access the ESP32 web server:

  • 1. Install Arduino IDE and ESP32 Board Support: Add https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json to Board Manager URLs and install the esp32 by Espressif Systems package.
  • 2. Select Board and Port: In Arduino IDE, set Board to DOIT ESP32 DEVKIT V1 (or ESP32 Dev Module) and select the appropriate COM port for the connected ESP32.
  • 3. Open Sketch: Open task1_esp32_web_led.ino in Arduino IDE.
  • 4. Configure Wi-Fi Credentials: Edit the ssid and password constants at lines 4–5 to match the target local Wi-Fi network.
  • 5. Compile and Upload: Click the Upload button (or press Ctrl+U). Arduino IDE compiles the sketch and flashes it to the ESP32 via the USB serial bridge.
  • 6. Open Serial Monitor: Set baud rate to 115200 bps and press the ESP32 EN (Reset) button. Observe the serial output until "WiFi Connected!" and the assigned IP address appear.
  • 7. Navigate to the IP Address: On any device connected to the same Wi-Fi network, open a browser and enter http://192.168.56.206 (use the IP shown in the Serial Monitor).
  • 8. Control the LED: Click TURN ON — the browser navigates to /on, GPIO 2 goes HIGH, and the onboard LED illuminates. Click TURN OFF — the browser navigates to /off, GPIO 2 goes LOW, and the LED extinguishes. The page reloads after each action and displays the updated LED state.

18. Problems and Solutions

Issues encountered during implementation and the corresponding resolutions applied:

Problem: Wi-Fi Credentials Mismatch

Issue: The Serial Monitor showed continuous . dots without ever printing "WiFi Connected!", indicating the ESP32 could not associate with the wireless access point.

Solution: Verified the ssid and password constants in the sketch matched the target network exactly (case-sensitive). After correcting the credentials and re-uploading, the connection was established successfully.

Problem: Page Not Accessible from Browser

Issue: Even after the ESP32 connected to Wi-Fi, the browser could not reach the page — the client device was on a different network segment.

Solution: Ensured the client device (laptop / mobile) was connected to the same Wi-Fi access point as the ESP32. Browser access was then restored immediately without any code change.

Problem: Serial Monitor Shows Garbled Text

Issue: Serial Monitor displayed unreadable characters instead of diagnostic messages.

Solution: The Serial Monitor baud rate was set to a value different from 115200 used in Serial.begin(115200). Changing the Serial Monitor baud rate to 115200 bps resolved the issue.

Problem: Slow Browser Response

Issue: Occasional slow response or timeout when clicking ON/OFF buttons — observed on a congested Wi-Fi network.

Solution: This is a known limitation of the single-threaded handleClient() approach. The ESP32 processes one request at a time. Moving to a less congested channel or using a 5 GHz band reduced latency. No code change was required.

20. Conclusion

This experiment successfully demonstrated the complete implementation of an ESP32-based embedded HTTP web server capable of controlling the onboard LED wirelessly through a standard web browser. Using only the WiFi.h and WebServer.h libraries bundled with the ESP32 Arduino Core, a fully functional browser-to-GPIO control pipeline was achieved with 106 lines of C++ code and zero external hardware components.


The ESP32 connected to the local Wi-Fi network in Station (STA) mode, obtained a dynamic IP address via DHCP, and began serving HTTP responses on port 80. Three URI routes (/, /on, /off) mapped browser interactions to digitalWrite() calls on GPIO 2, with each response including a live digitalRead()-based state indicator. All test cases — including single-device control, repeated toggle cycles, multi-device access, and power-on state verification — passed successfully.


The approach validates that microcontrollers with integrated Wi-Fi can serve as autonomous, infrastructure-independent IoT endpoints for real-world actuator control, serving as a scalable foundation for smart home automation, industrial monitoring, and educational IoT prototyping.
