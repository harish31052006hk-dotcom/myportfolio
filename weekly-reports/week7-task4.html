TASK 04 / FIREBASE CLOUD DASHBOARD Week 07 Project AuraIoT

Creating Firebase Realtime Web Dashboard

Build AuraIoT — a Firebase-powered dashboard for live environmental monitoring, relay control, authentication, automation, and telemetry export.

1. Overview

AuraIoT is a production-grade, responsive IoT cloud monitoring and control dashboard built on Google Firebase. Designed to bridge physical edge devices with modern web interfaces, the platform captures live sensor streams from the ESP32, visualizes ambient conditions in real time, and allows bidirectional appliance actuation.


The dashboard integrates live DHT11 temperature and humidity logging, LDR ambient-light sensing, manual and autonomous relay switching modes, secure Firebase Authentication for access control, persistent telemetry table recording, and instant CSV export for offline data analysis. The application is deployed on high-availability Firebase Hosting at dashboard-e6cea.web.app/automation.

2. Objective

The primary objective of this assignment is to build a cloud-connected IoT dashboard on Google Firebase that lets a user sign in, view live sensor readings, monitor the state of a connected device, and control the bulb relay from any web browser — without running a custom server.


  • Create a Firebase project (dashboard-e6cea) and enable Firebase Authentication, Realtime Database and Hosting.
  • Authenticate users with the Email/Password and Google providers before the dashboard is used.
  • Display live DHT11 temperature, humidity and LDR light readings read from Firebase Realtime Database.
  • Control the bulb relay with ON / OFF buttons that write to home/bulb/state, and provide Manual / Automatic modes with an LDR threshold.
  • Show history and export it through charts, a historical telemetry table and a CSV export button.
  • Deploy the dashboard on Firebase Hosting and document the setup honestly, including what still needs confirmation.

3. Problem Statement

Sensor nodes such as the ESP32 are small and are usually installed away from the person who wants to watch them. Reading their values normally needs a serial cable, or a local web page that only works on the same Wi-Fi network. Third-party dashboards can be used instead, but they are constrained in layout, features and access control.


This task addresses the following problem: How can sensor readings and a bulb relay be monitored and controlled from any browser, behind a login, using ready-made cloud services instead of a custom server?


The solution requires a cloud database that both the device and the web page can reach, a login system to decide who may open the dashboard, and a hosting service to publish the page, all provided here by Firebase.

4. Introduction

Firebase is Google's application development platform. It bundles services such as Authentication, Realtime Database and Hosting, so a front-end developer can build a working cloud application with only HTML, CSS and JavaScript.


Realtime Database: a NoSQL cloud database that stores data as one JSON tree and pushes changes to every connected client within moments. This makes it a natural meeting point for an ESP32 that writes sensor values and a browser that displays them.


Authentication and Hosting: Firebase Authentication verifies who is signing in (here with Email/Password or Google), and Firebase Hosting serves the dashboard pages over HTTPS at dashboard-e6cea.web.app. Together with the database, these three services form the complete cloud side of the AuraIoT dashboard.

5. Basic Concept of Cloud Computing

Cloud computing means using computing resources such as servers, storage, databases and software over the internet, instead of owning and running that hardware yourself. The provider (for example Google) keeps the data centres running, and the user pays for or is given only what is needed. Resources can be started in minutes, can grow or shrink with demand, and are reachable from any device with a connection.

Remote Resources

Servers, storage and databases live in the provider's data centres and are used through the internet, so nothing has to be installed or maintained locally.

Why It Suits IoT

An ESP32 is small and has little memory. The device sends its readings to an always-online database, and any browser can read from the same database without the device needing a public IP address or its own web server.

Always-On Storage

The cloud keeps the history of readings, which a small microcontroller cannot store by itself, and makes them available for tables, charts and export.

6. IaaS, PaaS, SaaS and BaaS

The four service models differ in how much of the technology stack the provider manages for the user:

IaaS — Infrastructure as a Service

What it is: raw virtual machines, storage and networking; you manage the operating system and everything above it.

Example: Google Compute Engine, Amazon EC2.

In this project: not used directly. Firebase runs on Google's infrastructure, but no server is created or managed.

PaaS — Platform as a Service

What it is: a ready platform to run or host your own application code; the provider manages servers and the operating system.

Example: Google App Engine, Heroku.

In this project: Firebase Hosting is the closest match. The web files are uploaded with firebase deploy and Google serves them over HTTPS.

SaaS — Software as a Service

What it is: a finished application that is simply used in the browser.

Example: Gmail, Google Docs.

In this project: the dashboard is a custom app, not a SaaS product. Only the Firebase Console was used as a ready-made management tool.

BaaS — Backend as a Service

What it is: ready-made backend features (login, database, storage) that a front-end app calls through an SDK, with no custom server code.

Example: Firebase, Supabase.

In this project: Firebase Authentication and Realtime Database act as the backend of the dashboard.

7. What Is a Cloud Platform?

A cloud platform is a collection of online services that developers use to build, store, secure, deploy and reach their applications, without owning the machines behind them. Typical services are databases and file storage, user authentication, web hosting, and tools or consoles to manage everything remotely. Google Cloud and Firebase are examples; Firebase is the part aimed at app and web developers.

8. What Is a Database?

A database is an organised store of data that programs can save to and read from, and that keeps the data after the program stops. A relational database uses tables with rows and columns. A NoSQL database such as Firebase Realtime Database instead uses a flexible structure, which for Firebase is a tree of JSON objects.

A database is useful for IoT because several things need a shared, persistent place to meet:

Sensor Readings

The device writes the latest temperature, humidity and light value, and the dashboard reads them.

Device Status

Whether the device and its relay are currently on, off or online.

Control Values

A command such as bulb ON or OFF, or a mode setting, written by the dashboard and picked up by the device.

History

Older readings are kept so they can be shown in a table or chart and exported.

9. Firebase Realtime Database

Firebase Realtime Database is a cloud-hosted NoSQL database that stores all data as one large JSON tree and keeps connected clients in sync as the data changes. Each piece of data lives at a path, for example home/bulb/state, and a path can hold either a single value or more child nodes.

JSON Tree Structure

There are no tables. Nodes are nested inside nodes, and a path such as home/bulb/state walks down the tree from the root. The real top-level nodes of this project are listed in Section 16.

Reading Data

With the JavaScript SDK, get() reads a path once and onValue() subscribes to it. Values can also be viewed directly in the Firebase Console.

Writing Data

set() replaces the value at a path. The dashboard's ON / OFF buttons do this for home/bulb/state (the page states "Writes directly to home/bulb/state"). Values can also be edited by hand in the console; the project README records that the dashboard was tested this way.

Real-Time Updates

When a page calls onValue() on a path, the SDK keeps a persistent connection to the database open. When any client or device changes that path, the new value is pushed down the connection and the page updates without a refresh. The RTDB Connected badge in the dashboard header shows this connection (Figure 21.1).

Support for IoT Monitoring

The ESP32 and the browser both reach the same database. The device writes sensor values, the browser listens, and the browser writes commands the device can listen for. The device-side program belongs to Task 05; this task covers the cloud and web side.

10. Cloud-Based Dashboard

A cloud-based dashboard is a web page that does not hold its own data. It connects to a remote database, reads the current values, and draws them as gauges, status badges, charts and tables, usually updating itself as the data changes. Because the page and the data are both online, the dashboard works from any browser that can reach the hosting URL.

11. Authentication and Login System

A login system makes a user prove who they are before the application shows its private pages. For this dashboard that matters because it can switch a physical bulb, so the controls should not be open to everyone who finds the web address. Firebase Authentication does the hard parts (checking credentials, handling Google sign-in and keeping the session), so the app does not have to store passwords itself.

19. Explanation of Important Code Sections

Explanation of the code that is available (Section 18). The listener, login and control code belongs to the missing dashboard source and is therefore not explained line by line.

ES Module Imports (lines 1–2)

Loads the Firebase App and Realtime Database modules from the gstatic CDN, version 10.7.1. initializeApp starts the SDK; getDatabase, ref, onValue, set and get are the database functions made available to the dashboard.

firebaseConfig (lines 4–10)

Holds the project identity: authDomain (used by Firebase Authentication), databaseURL (tells the SDK which Realtime Database to open), projectId and storageBucket. The apiKey is redacted.

initializeApp (line 12)

initializeApp(firebaseConfig) creates the Firebase app instance that connects this web page to project dashboard-e6cea.

getDatabase (line 13)

getDatabase(app) returns the database handle db. Other dashboard files attach to db with ref(), onValue() and set(), for example to write home/bulb/state.

firebase.json

Tells Firebase Hosting to publish the current folder ("public": ".") and to skip firebase.json, hidden files and node_modules when deploying.

24. Learning Reflection

Before this task I thought of a dashboard as just a web page. Building this one showed me that the page is only the front, and the real work happens in the cloud. I did not have to write or run my own server, which is the Backend-as-a-Service idea from Section 6.

☁️

Cloud Computing

I learned that the cloud is a shared place both the device and the browser can reach, so the ESP32 does not need its own public web server.

🔥

Firebase Services

Authentication, Realtime Database and Hosting each solve one part of the problem, and I only had to configure them instead of building them.

⚡

Real-Time Database Communication

The database is a JSON tree and a page can listen to a path, so a value changes on screen without a refresh. The RTDB Connected badge and the ON/OFF buttons writing home/bulb/state made this easy to see.

🔐

Authentication and Authorization

My login stops people from using the dashboard page, but my database rules are still open for reading and writing, so the data itself is not protected yet. Fixing that is the first thing I would do next.

📊

Dashboard Development

Gauges, status badges, a threshold slider, charts and a history table all come from the same database values, and small habits like showing -- until data arrives matter.

🔄

Connecting a Web App to Cloud Data

A small firebaseConfig object links the page to the project. I kept the API key out of what I share and documented the real database structure instead of an imagined one.
